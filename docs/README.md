# docs/ map

This is the table of contents for `docs/` and `docs/adr/`. Read the one-line summary here first; open the actual file only when working in that area.

Specular is the Rust app under `native/` (start with [`native/README.md`](../native/README.md) and [`native/CLAUDE.md`](../native/CLAUDE.md)). ADRs 0001 to 0038 were written for the Electron app, which was deleted; its source is in git history at `bc5253fa`. Their decisions about behavior hold where the Rust app ported them. Their mechanisms (IPC, `aboveView`, the Y.Doc, `WebContentsView`) are history.

## ADRs

- [0001 — Click-to-enter frame focus replaces rasterization-dependent gate](adr/0001-click-to-enter-frame-focus.md) — aboveView is the single input authority; click enters native focus instead of waiting on bgView rasterization.
- [0002 — Canvas-anchored overlay UI in aboveView](adr/0002-canvas-anchored-overlay-ui.md) — entity chrome/menus render as aboveView overlays anchored to canvas coordinates, not embedded page chrome.
- [0003 — `Page` as the canonical name for live web items](adr/0003-page-as-canonical-name-for-live-web-items.md) — renames `frame` → `page` across types, IPC, components, and docs.
- [0004 — Text affordances and the Specular spec-extension convention](adr/0004-text-affordances-and-spec-extensions.md) — splits Text/Sticky note/Document into one `text` kind with a `textStyle` field, plus the `specular.*` JSON Canvas extension convention.
- [0005 — Unified `Tool` concept](adr/0005-unified-tool-concept.md) — merges pendingPlacement/AnnotationMode/inspect into one `activeTool: Tool` discriminated union.
- [0006 — Unified comment tool (subsumes region-select)](adr/0006-unified-comment-tool.md) — one comment tool handles element/point clicks and region drags; amended by 0029 for page-anchored regions, and by a 2026-09-26 amendment moving the draft's composer off the canvas into the sidebar.
- [0008 — Unified canvas-item popup, selection-driven and tool-driven](adr/0008-unified-canvas-item-popup.md) — one `CanvasItemPopup` component replaces per-kind menu implementations.
- [0009 — Tool variants live in popup state, not in the `Tool` union](adr/0009-tool-variants-in-popup-state.md) — `shapeKind`/`brushType` move out of the `Tool` union into popup-managed tool defaults.
- [0010 — Main is the sole shortcut dispatch site](adr/0010-main-as-sole-shortcut-dispatch-site.md) — **Proposed** — consolidates keyboard shortcut handling (currently split across 3 locations) into main.
- [0011 — Page focus respects native shortcuts](adr/0011-page-focus-respects-native-shortcuts.md) — **Proposed** — a keyboard-focused page should see native shortcuts (Cmd+Z etc.) before app-level handlers.
- [0012 — Alignment guides are visual-only](adr/0012-alignment-guides-are-visual-only.md) — FigJam-style alignment guides render but never pull; grid-snap remains the only magnetic drag force.
- [0013 — Popup menus v2: palette, text size, cross-kind morph, toolbar regrouping](adr/0013-popup-menus-v2.md) — **Proposed** — locks down popup visual design decisions left soft by ADR 0008/0009.
- [0014 — Canvas stack order and the Notes/Pages sidebar](adr/0014-canvas-stack-order.md) — **Proposed** — flat `entityOrder` + group-contiguity invariant defines front-to-back stacking; sidebar splits into Notes/Pages sections.
- [0015 — Auto-layout groups](adr/0015-auto-layout-groups.md) — **Proposed** — Figma-style auto-layout: selected group packs children into row/grid with reorder-on-drag.
- [0016 — Tools as a capability registry](adr/0016-tools-as-capability-registry.md) — **Proposed** — unifies per-tool axes (enablement, palette, cursor, popup, bindings) behind one registry, extending 0005's identity unification.
- [0017 — Scroll does not pan the canvas in browser mode](adr/0017-scroll-does-not-pan-the-canvas.md) — plain wheel/trackpad scroll only pans in canvas mode; browser mode scroll stays native to the page.
- [0018 — Cloud sync, canvas sharing, and agents as peers](adr/0018-cloud-sync-and-canvas-sharing.md) — **Proposed**, no code landed — architecture sketch for server-optional cloud access to Y.Doc-backed canvases.
- [0019 — Canvas as a document: verb-primary CLI over one entity-kind registry](adr/0019-canvas-as-document-cli.md) — CLI surface becomes verb-first (create/move/delete) dispatched through one `CanvasEntityKind` registry instead of per-kind commands.
- [0020 — Delete Browser Mode for Focus Selection](adr/0020-delete-browser-mode-for-focus-selection.md) — removes the separate tab-based Browser mode; replaces it with an ephemeral Focus selection camera command.
- [0021 — Focus Session as a First-Class Concept](adr/0021-focus-session-as-first-class-concept.md) — promotes focus selection from a presentation-only camera command to a stateful session concept.
- [0022 — Pages adopt select-first / interact-second interactivity](adr/0022-pages-select-first-interact-second.md) — a single selected page is no longer automatically interactive; selecting and interacting become separate steps.
- [0023 — Markdown note content mirrored into the Y.Doc for undo](adr/0023-note-content-in-ydoc-for-undo.md) — note/document text edits are mirrored into the Y.Doc so Cmd+Z undoes edits instead of destroying the note.
- [0023 — Renderer-owned camera and GPU-composited pan/zoom](adr/0023-renderer-owned-camera-gpu-panzoom.md) — **Rejected** — attempted and abandoned; moving camera/pan-zoom ownership to the renderer gave no felt improvement and measured worse; kept as a record of what not to retry.
- [0024 — The entity-kind registry spans runtime state and persistence](adr/0024-entity-kind-registry-spans-runtime-and-persistence.md) — extends the ADR 0019 registry so `serialize`/`defaultSize` are actually dispatched instead of dead interface surface.
- [0024 — In-process integration suite replaces the Electron smoke suite](adr/0024-in-process-integration-testing.md) — replaces the slow/ungated Electron smoke suite with an in-process integration suite that exercises real IPC handlers.
- [0025 — Single workspace mutation seam](adr/0025-single-workspace-mutation-seam.md) — one owner for the dirty→autosave→layout→undo-boundary ritual instead of it being hand-sequenced at every mutator.
- [0026 — Arrange tidies in place; distribute folds in](adr/0026-arrange-preserves-footprint.md) — splits Arrange (repack to reading order) from Distribute (even gaps in place, preserves layout); retires the standalone Distribute button/verb.
- [0027 — Sync sets decouple navigation sync from groups](adr/0027-sync-sets-decouple-navigation-sync-from-groups.md) — replaces the per-page `linked` boolean (scoped by group) with independent sync sets, so linked pages no longer need to share a group.
- [0028 — Retire the chrome-header slot model](adr/0028-retire-chrome-header-slot-model.md) — removes the unbuilt chrome-header band from entity rects (ADR 0002 §1); entity rect == body rect.
- [0029 — Presence acts are anchored to truth](adr/0029-presence-acts-anchored-to-truth.md) — presence reflects real dispatch timing and never speculatively invents causality.
- [0030 — Interaction sync is semantic, not positional](adr/0030-interaction-sync-is-semantic-not-positional.md) — synced page interaction resolves semantic locator bundles on each peer.
- [0031 — Page-anchored entities (the "hook to a page" utility)](adr/0031-page-anchored-entities.md) — generalizes URL-gated page-anchoring into a reusable utility for content tied to a page.
- [0032 — Element attachment](adr/0032-element-attachment.md) — page-anchored items render corrected by a derived live DOM-element reference so ink survives reflow.
- [0033 — The space folder is user-chosen, and one space is open per window](adr/0033-user-chosen-space-folder.md) — **Accepted** — replaces the hard-coded `userData/workspaces/default/` with a folder the user picks in onboarding/Settings; migration and missing-folder cases prompt rather than guess; retires "workspace" from the vocabulary (space = folder, canvas = document, tab = open canvas).
- [0035 — Pages are frozen while the app is idle, never hidden](adr/0035-idle-cpu-throttling-for-pages.md) — **Accepted** — an unfocused window is not a hidden one to Chromium, so idle pages get `Page.setWebLifecycleState('frozen')` rather than `setVisible(false)`, which would blank the agent screenshot path; agent traffic and awake holds (recording, tracing) keep pages at full speed. Postmortem on why `Emulation.setCPUThrottlingRate` was abandoned (200µs signal loop, ~4k wakeups/s per page).
- [0036 — A diffed runtime store replaces the whole-scene broadcast](adr/0036-diffed-runtime-store.md) — **Accepted** — a normalized store plus a keyed patch bus makes fine-grained updates the default: mutators emit patches, the layout pass diffs, `layoutUpdate` stays the reconcile baseline, and each renderer is routed only the slices it reads. §6 records why `viewportNudge` was later deleted: renderers projecting canvas-space geometry locally (`docs/plans/camera-local-projection.md`) made the camera a slice patch like everything else.
- [0037 — A pan does not freeze its pages](adr/0037-pan-does-not-freeze-its-pages.md) — **Accepted** (its freeze/park machinery was deleted by ADR 0038, which made every page a texture all the time — on desktop; a browser tab cannot offscreen-render a cross-origin iframe, so this ADR is the presumptive substrate for a web target and is written to be re-derivable from) — the snapshot freeze is for gestures that change scale: a zoom re-rasters every page every tick and parking stops that, while a pan changes no scale, so its pages are already composited and parking would only cost a re-raster on unpark. Postmortem on the pan freeze that was built, measured, and reverted, and on why the two fixes that did work (the snapshot key, the dot grid) were both larger than it.
- [0038 — Offscreen GPU-texture compositing for live pages](adr/0038-offscreen-texture-canvas-for-live-pages.md) — **Proposed, implemented on branch `claude/offscreen-rendering-canvas-c81a4k`, pending manual validation** — spike (Offscreen Rendering Lab) measured native-compositor backpressure scaling badly with page count in the current WebContentsView architecture (62%→97.5% GPU busy from 9→20 pages); a follow-up animated-content spike found bitmap-JPEG's synchronous per-frame encode collapses to ~1/8th native rate under concurrent page animation while shared-texture holds full rate, reversing the initial JPEG-first call to shared-texture-first. Every page now hosts as an offscreen `BrowserWindow` composited as a texture; the Post-build validation checklist is the gate to Accepted.
- [0039 — Render and UI stack for the Rust canvas](adr/0039-rust-canvas-render-stack.md) — **Accepted** — bake-off for the Rust rebuild on wgpu 30: canvas items draw in the compositor's own pass (SDF shapes, glyphon text, lyon strokes), panels are egui in a second pass, and vello and GPUI are both turned down. Vello builds on wgpu 30 but is 2 to 3 times slower with dense text and copies page textures into its atlas. GPUI is Metal-only on macOS, asserts YCbCr on its surface element so BGRA page IOSurfaces abort, and owns the event loop.
- [0040 — GPUI Kit as the shell around our own canvas view](adr/0040-gpui-kit-hybrid-shell.md) — **Accepted** — spike of the hybrid ADR 0039 did not test: one GPUI window, GPUI Kit 0.7.1 for toolbar, sidebar, menus and dialogs, and our unchanged wgpu compositor drawing the canvas and its CEF pages into a child `NSView`. Works with caveats. Both renderers hold 120 Hz and CEF runs unchanged inside GPUI's `NSApplication`. The canvas view must sit below GPUI's transparent layer: above it, every popover is hidden and a resize shows a one-frame gap. GPUI's key events still carry no key code, so pages get keys from an `NSEvent` monitor. Canvas-anchored UI stays in our pass. The dependency is one maintainer's weekly snapshot of Zed's GPUI.
- [0041: A typed document with inverse-command undo, and no yrs](adr/0041-typed-document-inverse-command-undo.md): **Accepted**. The Rust rebuild keeps one copy of the document as typed structs. Every change is a `Command` whose `apply` returns its inverse, undo is a stack of inverses, and there is no CRDT. `.canvas` files from Electron round-trip byte for byte. No comparison against yrs was measured.
- [0042: One update, view, render loop, with effects as the only I/O](adr/0042-update-view-render-loop-effects-only-io.md): **Accepted**. `update(&mut App, Event) -> Vec<Effect>` does no I/O, `view` builds a display list with no GPU, and the shell runs every effect. Time and page answers arrive as events. This is why the Rust suite and the headless scenario scripts run with no window.
- [0043: Each canvas keeps its own state in a Space](adr/0043-per-canvas-state-in-a-space.md): **Accepted**. Every canvas of the open folder is loaded with its own document, undo history, camera and selection, so undo survives a switch and an agent can add pages to a background canvas. A switch closes and recreates page hosts. Switch cost and memory were not measured.
- [0044: UI as pure models with replaceable renderers](adr/0044-ui-as-pure-models-with-replaceable-renderers.md): **Accepted**. Toolbar, popups, sidebar, menus, chat and settings are functions from `&App` to plain data. A built-in renderer draws them for the winit shell and headless runs, and GPUI Kit draws them in the real shell. The cost is two renderers until one is retired.
- [0045: An item view is session state, not a mode](adr/0045-item-view-as-session-state.md): **Proposed**, not yet reviewed. A tab shows one page alone at its stored size, or one Document as a reading column, with a fitted camera. Which view is showing is one session value, hiding is one predicate where a page's scroll already hides things, and the ADR lists every reader so the per-mode branching of ADR 0020 does not come back.
- [0046: agent-browser announces its acts and waits for the cursor](adr/0046-agent-browser-announces-its-acts.md): **Proposed**, not yet reviewed. In the Rust app a patched agent-browser sends `Specular.willAct` with the point before each targeted verb, the app's own CDP proxy holds the answer until the agent cursor is drawn there, and agent-browser resolves again and dispatches. The intent route, the box-model reading and the dwell timer of ADR 0029 are not ported. Moving the verbs into the app was turned down because refs would need the whole dispatcher.
- [0047: A thread's avatar is the Prism, drawn on wgpu and read back into GPUI](adr/0047-thread-avatar-prism-on-wgpu.md): **Accepted**. The Kit shell's thread avatar runs three's own WGSL, dumped from the web build's WebGPU calls and checked pass by pass. It draws on the compositor's device, builds its renderer off the main thread, and reaches GPUI as a read-back image because GPUI's `surface()` takes no alpha. Each thread's clock runs only while its agent works, and a live avatar wakes itself on a timer: 30 fps for a thread's, 60 for the run bar's tumble.
- [0048: CRDT sync as a yrs mirror of the typed document](adr/0048-crdt-sync-as-a-yrs-mirror.md): **Proposed**, not yet reviewed. A shared canvas keeps a yrs document beside the typed one, writes every command into it and projects peers' changes back as commands. Undo takes back only your own edits, stack order is fractional keys, and note text merges character by character.
- [0049: The view-and-comment web client runs the app's own crates](adr/0049-view-and-comment-web-client.md): **Proposed**, not yet reviewed. A share link opens the Rust app itself compiled to WebAssembly, drawing on WebGPU or WebGL2, with pages as their published snapshots. A viewer can pan and comment but not edit: input is filtered and any other change is put back. Comments are stored on the server as `.canvas` annotations and merged back by id. Polling, not a socket, until live editing lands on ADR 0048.
