The stack

Roads 7, 8 and 9 aren't three alternatives. They're four layers and a choice of transport — local by default, sync when you want it, a link when you need one, and cloud agents throughout, with you never holding a readable copy of anyone's work.

Why this order

Each layer is useful on the day it ships, and no layer commits you to the one above it.

  • L1 pays for itself immediately. A canonical, stable-ordered serializer plus a Yjs update log on disk is what makes an agent editing a .canvas file safe today — no half-written file, no lost concurrent edit. It happens to also be the exact substrate both Road 7 and Road 8 need. Build it for the local case; get the sync case free.
  • L2 is Road 6's product work — author fields, a task-granularity diff, an activity timeline. It is wasted under no scenario and it's the layer that makes agent delegation actually usable rather than merely possible.
  • L3 is one interface with two implementations, which is the only abstraction in this whole exploration that earns its keep. A bucket driver and a git driver both do: list what's new, fetch it, append mine. Users pick whichever infrastructure they already have.
  • L4 is a build target, not a service — except the comment endpoint, which is the single piece of infrastructure you run.
  • L5 stays optional and per-canvas. Not a product-wide custody decision. If it ever ships, it ships for the canvases someone deliberately opts in.

What you can claim, and it's true

"Your canvases live where you put them. We never hold a copy."

Not a cryptographic claim, so no key management, no recovery phrases, no support tickets from people who lost a passphrase and lost a year of work. Just an architecture where the storage credentials were never yours.

And unlike Road 5, it doesn't foreclose the future: their storage holds plaintext, so their search, their backups, their agents all work on it. The features E2EE kills are alive here — they just run on the user's side of the line.

Worth stating plainly, because it's the result the first six roads couldn't reach: remote agent edits and zero custody are compatible, and the way you get there is by not being the one who stores things. Road 5 tried to solve the same problem with encryption and failed at exactly this point — a cloud agent has to decrypt, so somebody's server sees plaintext. Here nobody's server does, because the agent runs against storage the user already trusts.

The risk this stack carries

The setup wall is the whole bet. Both transports ask the user to bring infrastructure. If "how do I sync?" is answered with "create a bucket" or "connect a repo," a large share of the design audience stops there — and the developer half, who won't, is the half least likely to need convincing about anything.

The mitigation everyone reaches for is a hosted default on the same driver. It works, and it quietly converts the claim from "we cannot read your work" to "you can opt out of us." That's still a good product. It just isn't the differentiated one, and it's worth deciding on purpose rather than discovering after the onboarding metrics come in.

The version of this that stays honest: a first-run choice, not a default with an escape hatch. Local-only, your storage, or ours — asked once, in plain language, at the moment it matters.

What's still deferred

  • Live co-editing. Two cursors in one canvas is L5, and L5 may never come. Everything below it is turn-taking.
  • A zero-setup share for non-technical reviewers requires the hosted publish destination (Road 9C). Small custody, deliberately taken.
  • Binary assets under git remain awkward. The bucket transport handles them better; a content-addressed store shared by both is the fix, and it isn't free.
  • Undo versus history. Two timelines, one Cmd+Z. Unsolved on every road, and it gets sharper the moment a pull can change the canvas under you.

The strategic read: the first six roads framed privacy and collaboration as opposed, and Road 5 as the expensive way to have both. This stack gets most of both by asking a different question — not "how do we hold data safely?" but "what if we don't hold it?" It costs live co-editing and it costs onboarding friction. It buys cloud agents, sharing, version history and a trust claim that needs no cryptography to be literally true.
