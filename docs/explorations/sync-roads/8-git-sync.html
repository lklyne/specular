That table is the argument for this road. Road 6 correctly identified the missing primitives and then priced them as new product work. Half of them are a dependency away, in a tool the frontend half of the audience already has open.

The trick that makes it work

Commit the CRDT log, render the JSON

A raw .canvas file is a bad merge target: dragging one entity rewrites coordinates, reordering churns the array, and two people editing different corners of the same canvas produce a conflict a designer cannot resolve.

So don't merge the JSON. Commit both, and let each format do the thing it's good at:

foo.canvas          ← generated, canonical, diffable, .gitattributes: merge=ours
foo.canvas.log      ← append-only Yjs updates, merge=union

Yjs updates merge in any order, so a union merge driver on an append-only log is always correct — no conflict is possible. After merge, the app replays the log and regenerates foo.canvas deterministically. The JSON exists for humans, diffs, agents and review; the log exists for correctness.

This is Road 8's equivalent of Road 5's URL-fragment trick: one existing mechanism, used precisely, turning an apparently blocking problem into a config line.

What you get

  • Cloud agent edits as pull requests. The strongest agent story on the map. An agent gets repo access, works on a branch, and hands you a diff you review and merge — in a review UI that already exists and that you didn't build.
  • Discrete versions. Road 3 flagged that "what changed since you last looked" is trivial with snapshots and impossible in a live CRDT. Here it's a commit range, and every share link can point at a specific one.
  • Branching as a design feature. Explore a variant of a layout, keep it or throw it away, without polluting the canvas. No spatial tool in this category has this, and for iteration work it's genuinely differentiated.
  • Zero custody, zero ops. Same absence as Road 7. Their remote — GitHub, GitLab, a bare repo on a NAS, a folder in their own storage.
  • The audience is half-ready. "Designers and frontend developers." For the developers, git isn't friction, it's home — and it makes Specular a peer of the repo the design is about, not a separate silo.

What you give up

  • Binary assets rot the repo. Screenshots, images, video — committed once, carried forever. LFS or a content-addressed sidecar store, and either way it's real work that Road 7 gets for free.
  • No live co-editing, no presence. Commit granularity. Two people work in turns, not at once.
  • Conflicts you can't fully hide. The log trick removes them from canvas content — but not from a renamed file, a rebase, a detached head, or a user who pushed from a machine that was offline for a week. Some day a designer sees the word "conflict" and you own that moment.
  • A worse setup wall than Road 7 for non-developers. Auth tokens, remotes, and the word "repository" all cost you people.
  • Your undo stack and git's history are two different histories. Deciding which one is authoritative — and what Cmd+Z means after a pull — is a genuine design problem, not a detail.

The sync is free. The spend is a canonical serializer, the log-plus-merge-driver setup, asset handling, and a UI that hides git from people who don't want to see it. Note that the canonical serializer is worth building anyway — it's what makes agent edits to .canvas files safe under any road.

Who does this

Obsidian Git. Logseq. TiddlyWiki on a repo. Excalidraw files checked into design-adjacent repos. Every dotfiles setup ever. The pattern is well-trodden for text; nobody has done it properly for a spatial surface, which is either an opportunity or a warning.

The strategic read: the cheapest route to remote agent edits on the entire map, because the review workflow, the attribution and the revert story are all pre-built and battle-tested. It composes cleanly with Road 7 — both are just transports behind one sync driver — and it's the only road where the second actor being a process rather than a person is a natural fit rather than a compromise.
