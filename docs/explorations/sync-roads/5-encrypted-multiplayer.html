Encrypted multiplayer

Real co-editing where the server is a relay that holds only ciphertext. Access is a cryptographic capability rather than a row in your database — sharing a link means sharing a key. You host the collaboration and cannot read it.

The trick that makes it work

A share link looks like …/c/abc123#k=<key>. Everything after the # is never sent to the server — browsers don't transmit the fragment. So the viewer's own browser downloads ciphertext, reads the key out of its own address bar, and decrypts locally. You get a zero-install web link and a server that can't read the document. This one browser behaviour is the difference between "E2EE means no web client" and "E2EE with a web client."

What you get

  • Collaboration without custody. The genuinely differentiated position: multiplayer, sharing, sync, and a promise that you cannot read any of it.
  • Sharing that composes with privacy rather than trading against it — which is the tension that started this whole exploration.
  • Agents as peers still works. An agent gets a key like anyone else.
  • A defensible story against Figma and Miro that isn't "same thing, smaller." Nobody in this category can say it.
  • Less duty of care. A breach exposes ciphertext. No employee can look. There is little to hand over.

What you give up

  • Every server-side convenience. No thumbnails, no server-rendered previews, no cloud screenshots, no full-text search, no moderation, no "recover my deleted canvas" beyond blobs.
  • Simple revocation. You can rotate keys so future updates are unreadable, but everyone who ever held a key still has what they downloaded. Revocation becomes a re-key, not a delete.
  • Key recovery. Same support burden as Road 2, multiplied by every person you shared with.
  • Maturity. This is the youngest tooling on the list.
Where the tooling actually is (2026):
  • Obsidian Sync ships E2EE vaults with collaborators today. Proof this is a product, not a thesis.
  • Jazz has E2EE, permissions and auth built into the sync layer and is usable now.
  • Keyhive + Beelay (Ink & Switch) is the most complete design — capability-based access control with a sync protocol built so the server can't decrypt — but is an explicit early preview, "not for production."

The catch for this codebase: Beelay is an Automerge protocol. Taking that route means leaving Yjs and the Durable Object substrate the spike already built.

Who does this

Obsidian Sync (shared vaults). Proton Docs. CryptPad. Signal, as the general shape — group membership as cryptography rather than a permissions table.

The strategic read: the road that dissolves the premise that privacy and multiplayer are opposed. It costs the most to build, forecloses every server-side feature, and would likely mean rebuilding the sync substrate on different foundations. It is also the only road where the thing you'd want to say about your product is true.
