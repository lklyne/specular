# After the Rune spike: the page path, idle, edges, the runner and actors

**For:** [ADR 0053](../adr/0053-page-frames-follow-the-display.md), [ADR 0052](../adr/0052-one-runner-one-state-document.md) and [ADR 0054](../adr/0054-every-editor-is-an-actor.md), plus two findings from [the Rune spike](./rune-spike.md).
**Started:** 2026-11-25, after [ADR 0051](../adr/0051-rune-shell-around-the-compositor.md) was deferred. Everything here is on the Kit shell. Results go in the log at the end, one entry a phase.

## Branches

Every phase builds on `claude/post-rune-followups`, which sits on `claude/rune-spike-record` (the ADRs and `Compositor::with_samples`), which targets `rust-native`. One commit or a few per phase; a phase is meant to become one PR. Phase 5 runs in parallel on its own branch, `claude/analytic-edges`, off `claude/rune-spike-record`.

## Phases

1. **Teardown order and a baseline.** The spike found that stopping CEF while the compositor still holds page IOSurfaces runs into Chromium's teardown watchdog (exit 2 in 6 of 40 runs, up to 9 s), and dropping the textures first fixed it. Check whether the Kit shell has the same order in `specular-shell` (`Runtime::poll_shutdown`, the window's close path) and fix it if so. Then take a release baseline of the Kit with the S6 bench (its scripts are at the tag `archive/rune-spike`, `native/bakeoff/rune-shell/scripts/bench-s6.sh` and `tools/s6_*.py`): idle wakeups and CPU with still pages, pans at 9, 20 and 40 pages, key to present. Later phases compare against it.
2. **A paint wakes the canvas** (ADR 0053 item 2). The page source signals the window when a frame is queued, so a paint does not wait for the next display tick or the 50 ms idle turn. The 30 Hz pump fallback and the idle turn stop being what delivers a frame.
3. **The entered page and a page in Fill paint at the display's rate** (ADR 0053 item 1), and the smaller fixes listed under its Decision: newest paint dropped at the six-frame cap, the retire callback registered only when something is already retired, pages painting while the window is occluded, the 250 ms forced-frame tail after a pointer move in an entered page, the LOD running twice a turn. Then try app-driven begin frames for the entered page (item 4) and adopt them only on the numbers the ADR names.
4. **Idle cost.** Measure again against phase 1's baseline (S6 had the Kit at 176 wakeups/s and 2.9% CPU with still pages, Rune at 32/s and 1.3%). Find what still wakes the Kit with nothing moving and remove it.
5. **Analytic edges, single-sampled pass** (ADR 0053 item 3), in parallel. Lyon meshes get their own anti-aliasing (feathered geometry or SDF segments), the pass runs at `Compositor::with_samples(.., 1)`, and the multiply blend is kept. S4 listed what stair-steps at 1 sample: freehand strokes, highlighters, edges, arrowheads, dashed outlines, and the outlines of diamonds, triangles, hexagons, parallelograms, chevrons and cylinders. Ships with a GPU readback test, as the ADR says.
6. **ADR 0052 without Rune.** Revise the ADR for the Kit shell first (which parts stand, which assumed Rune's headless window), then build what stands.
7. **ADR 0054, every editor is an actor.** Its Cmd+Z question is open and is Lyle's to answer. Build what does not depend on the answer; stop before what does and ask.

## Rules

- Per change: `cargo check` / clippy and tests for the touched crates. Before each phase's commit: the gate in `native/CLAUDE.md` (fmt, workspace clippy, workspace tests). No window smoke test per step; one by-hand pass per branch at the end, by Lyle.
- Release builds and `bundle-macos.sh` are allowed for measuring (phases 1, 3, 4), with `CEF_PATH="$HOME/.local/share/cef"`. Numbers only from release, three runs a case, with what else was running written down.
- Do not start or kill processes you did not start. Commit only your own files, by explicit path. Do not push; the orchestrator pushes.
- A phase that cannot finish commits what compiles, writes `BLOCKED` and the reason in the log, and stops.

### Phase 1, 2026-11-25. Teardown order fixed; Kit release baseline taken

- **Run:** debug CEF bundle, headless `--source cef --snapshot` runs on the spike's `cef-pages.canvas` (2 local pages) and `still-20.canvas`, before and after the fix; release CEF bundle, the Kit cases of S6's bench. **Read:** `Runtime::exit`/`poll_shutdown`, the Kit's close and Cmd+Q (`kit/shell.rs` `begin_exit`, `kit/canvas.rs`), the headless `shut_down`, the bench's `finish`. All four end through `Runtime::exit`.
- **Teardown:** the Kit had the spike's order. `exit` cleared its hosts but the compositor kept every page's imports and retired IOSurfaces until the window was dropped, after CEF had stopped (no render runs while closing, so nothing reclaimed them). Fix (`c5cdb079`): `Compositor::release_pages` forgets every page, waits for the GPU and drops the retired surfaces; `exit` calls it before the source stops. Before: 1 watchdog exit (code 2, 10.0 s) in 80 runs, the first after bundling; shutdown p50 ~65 ms (2 pages) / ~90 ms (20), tail to 2.0 s. After: 0 in 80, all exit 0, same p50; tails to 4 to 7.6 s remained in the 20-page set while another agent's `rustc` loaded the machine (load 28), so they are not attributed to the fix. The bench's 18 release window runs all exited 0. The Kit's rate (1/80) is far below the spike's 6/40, so the before/after difference is suggestive, not significant. No regression test: nothing headless can see CEF's watchdog, and the synthetic source does not care about the order.
- **Baseline** (`assets/post-rune-baseline.md`, with the exact commands): pan p99 15.7 / 15.4 / 9.2 ms at 9 / 20 / 40 pages, main thread 1.28 / 1.38 / 1.21 ms a frame, pump p95 0.20 / 0.14 / 0.14 ms; idle with still pages 175 wakeups/s and 3.2% CPU, 0 frames; memory 3,007 MB (browser + GPU) at 20 pages; key to present p50 8.3, p95 16.5 ms. No drift from S6's Kit column beyond its own spread. Not quiet: VM, Claude app, a dev server, and another agent compiling at the start; on AC.
- **For phase 2:** the idle wakeups (175/s, 30 pumps/s) are unchanged from S6, so the paint wake has a clean target. Pan 9 has 15 to 16 long frames in every run here and in S6, while 40 pages pans clean; worth a look when the paint path changes. `kit-baseline.sh` is in the baseline page; it needs the `archive/rune-spike` worktree.

### Phase 2, 2026-11-25. A paint wakes the canvas

- **Run:** release CEF bundles before (`7f239a24`) and after (`a24b5b06`), three runs a case: 19 still local pages plus one that flips its own background every 1.5 to 2.5 s (`--bench idle`, 40 s; the link rests between flips), `still-20` idle, and S6's flip page under 40 keys. **Read:** `paint.rs`, `page.rs`, `pump_timer.rs`, the Kit's `canvas.rs`, `canvas/pacing.rs`, `shell.rs`, the runtime's `frames.rs`/`demand.rs`; headless runs poll every 2 ms and are left alone.
- **Mechanism:** `PageSource::set_paint_wake` (default: ignored, which the synthetic source keeps, as its pages paint inside the pump). The CEF source calls the wake for the first `Frame` queued after each drain, from inside `OnAcceleratedPaint`; the Kit's wake only `try_send`s on a one-slot channel, and a GPUI task then calls `canvas::on_page_paint`. That draws at once unless a frame was presented less than a refresh ago or the link's next tick is due within 2 ms (`paint_draws_now`, table-tested); a deferred paint stays undrained, so no more wakes come until a tick takes it. While the link rests it always draws, and the draw restarts the link.
- **Paint to present** (ledger: each `cef.paint` to the end of the first frame after it, i.e. present returned): self-flip, link resting, p50 22.8 / p95 48.1 / max 51.8 ms (n 58) before, 0.89 / 1.38 / 1.41 ms (n 57) after. Flip page under keys: 4.70 / 7.04 before, 3.19 / 8.15 after, unchanged within noise: the 250 ms input tail draws on every tick, so the gate leaves the paint to the tick.
- **Key to present** (flip): p50 8.30 / p95 10.08 [8.53 to 18.90] before, 8.23 / 16.71 [8.70 to 16.73] after; the same ~1.25 s outlier every run. No change beyond S6's spread.
- **Idle, 20 still pages:** 177.2 / 176.3 loop turns/s, 30.3 / 30.4 pumps/s, 0 / 0 frames, browser CPU 2.3% [1.8 to 2.7] / 3.2% [3.0 to 3.3] (baseline page: 3.2%). Still pages queue no frames, so no wake fires; the CPU spread is the machine (load 4 to 12: VM, Spotlight indexing, Claude, a dev server; no other rustc).
- **For phase 3:** the input tail is now the only thing between an entered page's paint and the screen; removing it lets the wake deliver typing too. A covered window's paints still each cost a turn (the draw is refused); stopping pages painting while occluded removes that. The 30 Hz pump fallback and the 50 ms idle turn are untouched and no longer deliver frames; phase 4 can cut them.


### Phase 3, 2026-11-25. The page path's smaller fixes; display rate asked for, held at 60 by CEF

- **Run:** release CEF bundles before (`c665425e`) and after (`25d850a2`'s code), alternated, three runs a case, each waiting for load under 6 (it ran 3.3 to 6.0; VM, Docker, Claude, a VPN daemon; on AC). - **Cap drops oldest** (`b1783410`): confirmed, the newest paint was dropped. The oldest queued frame of the page's layer gives way; with none queued the page is invalidated once a slot frees. One rule test.
- **Latency outlier** (`a67e5c49`): the ~1.25 s sample was the script's third click, which paints nothing, resolved by the first key's paint 1.3 s later. Probe artefact, not latency. The probe now gives up on input unanswered for 100 ms (2 unresolved a run). One test.
- **Display rate** (`4490130b`): `PageLod::update` takes the display's rate (read from the window's screen, 120 here) for the entered, filling or prepared page; table row added. Measured: the entered page still paints 60/s before and after. Its paint timestamps are exactly 16.67 ms apart; asking 120 at creation does the same; `--disable-frame-rate-limit` gives 120 but 17k pumps/s. CEF 154's windowless begin frames are 60 Hz, so the code is in and waits on item 4 or a later CEF.
- **Occluded** (same commit): pages stop while the window cannot be seen. Four animated pages, minimised: paints 120/s to 0, turns 471/s to 49, cap drops 840 to 0 in 7 s. Found on the way: quitting while minimised spun forever (a stale rest with the link paused); fixed there.
- **Input tail, LOD once** (`25d850a2`): input that only reaches the entered page owes no frame and no 250 ms tail; `draw` grades pages only if the app changed since the chores. Flip page: key to present p50 8.36 to 7.21, p95 18.2 to 9.0 ms, max 1,273 to 25; paint to present p50 2.55 / p95 9.51 to 1.12 / 1.76 ms.
- **Unchanged:** pans p99 15.9/15.6/15.7 to 15.9/15.8/15.5 ms, main thread 1.40 to 1.45 ms a frame both; idle still-20 175 to 177 turns/s, 30.4 pumps/s, 0 frames, CPU 3.2% both.
- **Begin frames (item 4):** tried uncommitted, not adopted: 115 paints/s entered but key to present p50 21.8 ms. Numbers in ADR 0053 item 4.
- **For phase 4:** idle is where phase 2 left it (176 turns/s, 30 pumps/s): the 30 Hz pump fallback and the 50 ms idle turn are now the whole cost. `bench.sh idle` reruns it. 120 for the entered page is a CEF question, not ours.

### Agent wake, 2026-11-25. A page an agent drives paints while no one can see it

- **Built** (`d59be441`): every CDP message a client sends through a page's `PageProxy`, every `Specular.willAct` and every API page script marks the page driven for 5 s (`specular-interact/src/agent_wake.rs`, `Event::AgentDrove`, `App::agent_driving`, kept by the session clock and dropped on the tick). The LOD treats a driven page as in use: it paints at the display's rate when off the camera or in a minimised or covered window. The shell wakes the page before sending the message on, and `next_turn` wakes at the lapse. The window stays minimised; other pages stay asleep. One table test on the rule (`app/lod.rs`), mutation-checked both ways.
- **Run:** debug CEF bundles before (`371dc14e`) and after, one run each: one rAF clock page, the window minimised by the shell script (`menu-choose Window > Minimize`) at 10 s, then CLI verbs from 22 s with the unpatched agent-browser (plain CDP path). Ledger from `SPECULAR_RESIZE_TRACE`.
- **Before:** `eval window.n` 318 then 318 a second later (no rAF); `screenshot` took 1.74 s and showed frame 319; after `reload`, `eval` read n = 0 and the next screenshot (1.18 s) showed frame 2.
- **After:** `eval` 750 then 898 1.2 s later (120 a second, the display's rate); `screenshot` took 0.24 s and showed frame 927, between the evals around it (898, 950); after `reload` n = 26 and the screenshot (0.23 s) showed frame 54. Paints stopped and turns fell back about 5 s after the last verb.
- **Idle, minimised, no agent** (ledger, 30 s): 5 to 7 turns/s and 0 paints in both. Visible idle was not rerun; no agent leaves the path as it was.
- **Seen in both:** CDP screenshots of an 800x500 page come back 1600x1000 with the page tiled 2x2, and `cli-pages.sh` fails the same 6 cases from `find text "Next A" click` onward. Neither is from this change.

### Screenshot fix, 2026-11-26. The pump hurries while an agent drives a page

- **Found:** on this branch an API page screenshot (`POST /pages/screenshot`, the CLI's `screenshot`) showed the page's top-left quarter at double size; `rust-native` showed the whole page. Bisected over debug CEF bundles with `cli-pages.sh` to `e0d273e2` (phase 4, pump on CEF's asks with a 1 s fallback). As with loads, CEF does not ask for all the work a capture needs, so the capture ran before the page caught up.
- **Fix:** `PageSource::set_driven`; the shell sets it while any page is agent-driven (`settle_pages`), and the CEF source then holds the pump at the load rate, 30 Hz. Idle with no agent is unchanged.
- **Check:** `cli-pages.sh` has a "screenshot shows the whole page" case that samples the right of page B's shot. Three runs at load 25 to 30: 30 pass, 6 fail, the same 6 navigation cases (`find`, `wait --url`, `forward`, `reload`, `get title`, `canvas`) that fail on `rust-native`. The `add note` file case now waits up to 2 s for the file, which is written a turn after the answer; it was there at once in every run since.
